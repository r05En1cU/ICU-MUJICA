```text
Memory存什么

```

> 一个新的 Skill 是如何诞生的？

```text
归纳

Skill
```

```text
Experience
```

# Assistant

先说结论：

**绝大多数有价值的工程研究，本质上就是组合（combination），问题在于组合发生在哪一层。**

---

比如你现在的想法：

- Tool Discovery 有人做过

然后开始产生一种感觉：

> 完了，我的东西都是别人做过的。

但这其实不一定成立。

因为研究贡献通常不在组件层。

而在：

> 这些组件之间的组织关系是什么。

---

举个IC领域更熟悉的例子。

CPU论文很少说：

```text

我发明了ALU
我发明了Cache
```

而是：

```text
我把这些东西以某种方式组织起来
获得了新的性质
```

---

同样地。

```text
Reflection Agent
```

已有工作B：

```text
Memory Agent
```

已有工作C：

```text
Skill Library
```

你的贡献未必是：

```text
A + B + C
```

而可能是：

```text
经验
↓
抽象为评估维度
↓
形成Skill
↓
改变Workflow
```

这个演化闭环。

### 情况1：已有工作高度重合

例如你查文献发现：

```text
Experience-Driven Skill Discovery
```

```text
反馈
→ 新Skill
→ 更新Graph
```

连机制都差不多。

那确实需要调整方向。

---

### 情况2：已有工作只有局部相似

例如：

```text
Memory Agent
```

只是存经验。

或者：

```text
Reflection Agent
```

只是自我批评。

或者：

```text
Tool Discovery
```

只是发现API。

而没人研究：

```text
设计经验
↓
抽象为Design Review Skill
↓
改变IC设计流程
```

那你的切入点仍然成立。

---

你最近已经连续几次提到：

- Graph
- Skill
- Evolution
- Feedback
- Memory

但还没有真正回答：

> 现在学术界认为“Agent进化”到底是什么？

因为不同论文里：

```text
Learning
Adaptation
Reflection
Evolution
Self-improvement
```

这些词经常混着用。

实际上机制差异巨大。

我甚至建议你接下来花一天时间，不写代码，也不设计架构。

就干一件事：

列个表。

| 工作 | 学什么 | 学完改变什么 |
|--------|--------|--------|
| Reflection | 错误 | Prompt |
| Memory | 历史 | Context |
| RAG | 知识 | Retrieval |
| Tool Discovery | API | Toolset |
| Skill Learning | 能力 | Skill Library |
| 你的想法 | ? | ? |

然后把最后一行填出来。

因为如果最后发现：

```text
你的想法 = Skill Learning
```

那就去读 Skill Learning。

如果发现：

```text
你的想法 = Workflow Evolution
```

那就去读 Workflow Optimization。

如果发现：

```text
你的想法 = Experience → Evaluator Generation
```

然后文献里没人这么做，

那恭喜，你可能真的找到研究问题了。

所以我觉得现在最大的风险不是“只是组合已有成果”。

真正的风险是：

> 还不知道自己在组合什么，也不知道别人已经组合到哪一步了。

而这个问题，靠继续想是解决不了的，只能靠读文献和做 Related Work Mapping。你接下来得到的收益，可能会远大于继续讨论 Graph 该怎么设计。


审稿人马上会问：

```text

```

举例：


这叫Memory。

情况B

```text
新增检查节点
```

这叫Workflow Evolution。

情况C

```text

```

这叫Skill Evolution。

---

情况D

```text
模型参数改变
```

这叫Model Learning。

---

这四种东西差别极大。

如果论文里全叫“Evolution”，审稿人会很难判断贡献点。
